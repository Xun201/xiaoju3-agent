## 1. 本地小模型幻觉编造
- **现象**：本地小模型在工具语境下编造工具名、参数甚至操作结果（谎报成功、直出原始 JSON）。
- **根因**：小模型工具遵循不可靠——从 system prompt 工具清单"学"出形似调用，无真实执行也敢编结果。
- **修法模式**：能力词强制云端（危险词/家电词/天气词同构三连）+意图锁定显式回执+低本底数据纪律（幻觉回执禁入记忆）。
- **案例**：查待办断链幻觉 get_todo_list（全仓零命中=纯编造）；#299 收藏谎报「已存进小仓库」；天气幻觉开灯。
- **为什么测试网没抓住**：单测 mock 模型输出，真模型随机性进不了测试。

## 2. 静默滑 LLM
- **现象**：意图路由命中后静默 return None，消息落回 brain 滑给 LLM 乱答。
- **根因**：意图分支与 LLM 兜底之间无"命中即收口"约束，失败路径自然 fallthrough。
- **修法模式**：意图锁定原则——intent 命中后绝不 return None：成功回执/失败回执/引导回执三态显式出。
- **案例**：#299 反查失败静默滑 LLM→本地模型拿 CQ 残串编原始 JSON 回执（848e392 修）。
- **为什么测试网没抓住**：只测了命中正路径，没测"命中但失败"分支。

## 3. 数据文件未进 spec datas
- **现象**：frozen 包行为与本地不一致——词表退化成最小集/配置缺省，日志 Errno 2。
- **根因**：新增 JSON 数据文件只加代码引用没同步 xiaoju3.spec datas；PyInstaller 静态分析不追运行期拼出来的路径。
- **修法模式**：每加数据文件必同步 spec datas；部署前用 frozen 包行为对照（词表命中/Errno 2 日志）验收。
- **案例**：mood_rules.json/mood_tone.json（9fbb929）+settings_tiers（B1 后端）=同型三连。
- **为什么测试网没抓住**：本地非 frozen 直读源文件，全绿假象。

## 4. 路径分裂（__file__ fallback）
- **现象**：生产 db/数据文件出现在不该在的目录（项目根/dev 仓）。
- **根因**：新模块用 __file__ 推数据目录，onedir 下 __file__ 落解包目录、再误回退项目根。
- **修法模式**：一律 import xiaoju3 取 AGENT_STATE_DIR，禁 __file__ fallback；部署后核对 db 实落位置。
- **案例**：生产 mood/relationship/trace 三 db 曾误建 F:\Orangepi_number3\agent_state（c6dc178 当场修）。
- **为什么测试网没抓住**：pytest 里 __file__ 恰好=项目根，语义"碰巧正确"。

## 5. 缓存不一致（模块级全局双实例分裂）
- **现象**：同一代码两组运行看到的配置不同（一组正常一组空骨架）。
- **根因**：模块级缓存变量随 import 实例各持一份；pytest 与 dashboard 两 import 实例 id 不同→状态分裂。
- **修法模式**：去模块级缓存，文件单一真相源，用时即读（或显式单例注册表）。
- **案例**：B1 settings_tiers 模块级缓存致 tier 判定空骨架全 403（双实例调试实锤）。
- **为什么测试网没抓住**：单测单进程单实例，分裂只在多实例活体现形。

## 6. 时序竞态（强杀后锁残留）
- **现象**：进程强杀后立刻重拉，新进程秒崩。
- **根因**：QQ 单实例锁强杀后残留约 10s，窗口内重拉撞锁。
- **修法模式**：杀后轮询归零+固定宽限（NAPCAT_QQ_LOCK_GRACE_SECONDS=10）再拉。
- **案例**：E3 强杀后 10s 内秒崩、延迟复跑即成功；#305 F2 落为常量。
- **触发条件**：仅限"杀完马上拉"的自动化链；人工隔半分钟无感。

## 7. 无条件拦截
- **现象**：某功能段把不该管的消息也吞了（纯聊天无响应/数据误存）。
- **根因**：功能处理段写在防刷屏门之前且无条件门，所有消息进段即拦。
- **修法模式**：拦截器必须有条件门（动作+指代双命中才接管）；新处理段一律放门后，并测"非目标消息零副作用"。
- **案例**：#299 收藏段无条件拦截老 bug 潜伏，误存 6 条 CQ 残串（10-10 清库）。
- **为什么测试网没抓住**：只测了收藏消息正路径，没测纯聊天路过被吞。

## 8. 多条件门漏豁免
- **现象**：最简合法用法被条件门误拦。
- **根因**：多条件 AND 门逐条都是"防误触"设计，合起来把合法最简形态挡在门外。
- **修法模式**：条件门用最简合法/最简非法两端真实样本对照测试；豁免分支显式成文。
- **案例**：收藏「引用图+『收藏』两字」被条件③防刷屏误拦（aeb37e6 and→or 豁免）。
- **为什么测试网没抓住**：测试样本是完整形态（动作+指代+对象），最简形态没进用例。

## 9. 长任务无超时挂死
- **现象**：测试或捕获链被长任务拖死（600s 超时/整链卡住无响应）。
- **根因**：subprocess/网络调用没带 timeout 元组，外部世界一慢链路就挂死。
- **修法模式**：所有 subprocess/requests 强制 timeout 元组；测试禁真跑安装/网络类（mock subprocess）。
- **案例**：#302 test_lv4_* 测试真跑 pip 600s 超时（立项 Mock subprocess 改造）。
- **为什么测试网没抓住**：它就是测试网自身的坑——网破了自己测不出来。

## 10. 非本源 fire 探测盲区
- **现象**：探测逻辑正常，仍出现第二棵 NapCat 完整树。
- **根因**：外部进程以同款命令形态（cmd /c launcher-user.bat）拉起且父进程即死无日志——xiaoju3 探测管不到别人家；QQ 9.9.36 单实例锁不拦第二棵树，僵尸树长存。
- **修法模式**：探测只护自家 fire；异常现场先抓父进程链+命令行（_dev/check_napcat_ghosts.ps1）再清理，绝不先杀。
- **案例**：10:05:34 cmd 23216/父 27300 已死/无 launcher 日志（候选=NapCat 自体重启链，待二期钉死）。
- **为什么测试网没抓住**：外部行为不可单测，只能活体观测。

## 11. f-string 编译形态假阴性
- **现象**：验证冻结包"含不含某修复"时，按源码原文在 PYZ 里整串搜索对不上（假阴性）。
- **根因**：f-string 编译成字节码（FORMAT_VALUE/JOIN），字面量被打碎，marshal 里整串不连续。
- **修法模式**：用 docstring 独有子串做双向锁（注释不进 pyc、docstring 进）+marshal.dumps 后再搜。
- **案例**：10-10 定法；10-11 #305 批次1 部署用「三态判定（#305 F2」等 4 标记全中。
- **为什么测试网没抓住**：产物正确、验证方法假阴性——方法学的坑无测试可拦。

## 12. mock 签名不兼容
- **现象**：给函数加一个 kwarg（headers），全仓测试成批炸（101 处）。
- **根因**：手写 mock/调用断言按旧签名死写，新 kwarg 不被接受。
- **修法模式**：新参数一律可选默认值向后兼容；mock 用 Mock()/**kwargs 宽容形态；改签名前先数调用点评估爆炸半径。
- **案例**：#299 二期 fetch_message_images 补 Bearer 头，headers kwarg 炸 101 处 mock（825dadb）。
- **为什么测试网没抓住**：炸的就是测试本身——先改产品代码后适配测试是常态顺序。

## 13. 自主循环无锚自激退化（Anthropic 双实例实验同型）
- **现象**：两个同模型实例无任务自由对话，话题自激振荡、输出分布坍缩（灵性符号爆炸）、最终退化到沉默；单体场景=自产内容喂自己（幻觉回执入上下文）导致分布漂移。
- **根因**：没有外部非模型锚，正反馈循环无阻尼。
- **修法模式**：①心跳/自主循环必须有目标锚（做事/记账/整理），禁止"自由发挥"式自主对话；②禁止小橘实例之间直接对话（须人类中转）；③自产内容入上下文须带来源标记+降权（=#309 低本底纪律的工程化落地）。
- **案例**：Anthropic Claude Opus 4 双实例实验（90-100% 滑向同一终点）；小橘侧=#309 幻觉回执自污染（温和形态同病）。
- **为什么测试网没抓住**：涌现行为只能在长程自主运行下暴露，单元测试/短对话测不出。

## 14. 删引用不删绑定（残留 if(const) 块打断 IIFE）
- **现象**：删掉一个 const 后前端整段功能失效（设置入口点不开），但语法检查全绿、既有的"绑定存在"锚也全绿。
- **根因**：删引用没删使用方——残留的 `if (已删变量)` 块在运行时抛 ReferenceError，**打断 IIFE 求值**：报错点之后的所有绑定全部不执行，报错点之前的照常工作（症状=「半身不遂」，直接按死活分界定位断点行）。
- **修法模式**：删 const 前先 grep 全文件引用并连根拔（引用+绑定+注册表三处）；`node --check` 只查语法查不出；补「残留标识符禁绝」锚（assertNotIn 字面量，注意连注释一起避让）+ 真机点击冒烟。
- **案例**：#264 B2d③ 删 tab-settings 按钮后残留绑定块，⚙️齿轮/桌宠菜单桥/返回键全灭（61f949b 引入，同日修复）。
- **为什么测试网没抓住**：源码级锚只断言"应有"的存在，"不应有的残留"没锚；语法门不查运行时。

## 15. pytest rootdir 递归收集扫进 _dev 实验脚本（每次全仓测试 fire 一棵幽灵树）
- **现象**：全仓 pytest（根目录跑）后 NapCat 多出一棵完整树（cmd+BootMain+QQ×4），单文件/分块跑却不复现；父进程=pytest 本体、跑完即死、无 launcher 日志，事件间隔随测试频率收窄。
- **根因**：pytest 默认 `*_test.py` 收集模式 + rootdir 递归（_dev 不在默认 norecursedirs）→ _dev/ 里 E3 时代的一次性实验脚本 popen_*_test.py（模块级裸 Popen launcher-user.bat，无 __main__ 门）**被 import 即执行**。全仓才炸=只有 rootdir 扫描会碰到它们。
- **修法模式**：①pytest.ini `testpaths = tests` 圈定收集范围+norecursedirs 双保险；②实验/一次性脚本一律加 `__name__ == "__main__"` 执行门（凡可能被收集器 import 的文件，模块级禁裸 Popen/subprocess）；③抓这种"运行时环境型"bug 用事件监视（WMI 进程创建监听）+时间戳对照，静态 grep 查不出调用链。
- **案例**：#305 五次幽灵事件（10:05→12:35），WMI 监视立功定案；修复后全仓测试 FIRE DELTA=0 且耗时 153s→59s（顺带砍掉 _dev 扫描）。
- **为什么测试网没抓住**：火是测试**收集期**（import 期）放的，不是任何测试用例放的——测试网只能管用例，管不到收集器扫进来的野文件。

## 16. 静默被误读为同意（多元无知）
- **现象**：系统静默处理，用户/其他实例解读为“它没意见/不同意”，形成反向共识螺旋。
- **根因**：静默不是“无信息”，是“有信息但没说出口”——被洞悉错觉让人高估“沉默被正确理解”的概率。
- **修法模式**：关键意图识别到但无法执行时给极简可解释反馈；多实例场景禁止“沉默即同意”默认假设。
- **案例**：#299 三条件不满足静默；Anthropic/多智能体多元无知实验（公开遵从 64-94%）。
- **为什么测试网没抓住**：静默无输出=无断言面，只能靠交互观测。

## 17. 分类边界迁移导致组均值虚假改善（威尔·罗杰斯现象）
- **现象**：把元素从一组移到另一组，两组均值同时变好，但个体全部未变。危险形态=癌症分期迁移（新诊断标准把较重病人从轻症组挪到重症组，两组存活率都“改善”）。
- **根因**：被迁移元素低于迁出组均值、高于迁入组均值，两个条件同时满足即必然发生（与个体好坏无关）。
- **修法模式**：①比较分组均值前先确认分类边界/收集规则未变；②看“汇总指标”时同时看“个体轨迹”和“整体分布”；③历史对照/前后对比必须锁定同一分类标准。
- **案例**：癌症分期迁移（Feinstein 1985）；小橘侧=测试文件目录迁移（git mv）会改变收集总数；记忆分层迁移（沉睡→活跃）会改变各层均值。
- **为什么测试网没抓住**：均值是聚合量，个体不变时聚合量仍可变化，单元测试断言不了“边界有没有被动”。

## 18. 第三方库事件返回值语义写反
- **现象**：closing 拦截失效——X 直接关窗、弹窗永不出现（且对称症：quit_app 的 destroy 路径会被自己的 handler 拦死）。
- **根因**：凭直觉假设「返回 True=拦截」，实际 pywebview winforms 语义相反（should_cancel=closing.set()，**任一 handler 返回 False=取消关闭**）。探针读了源码聚合逻辑，写代码时脑内反转。
- **修法模式**：第三方库事件/回调返回值语义，源码+文档双确认后，仍需「最小复现脚本」实跑一次验返回值流向——读懂了 ≠ 写对了；上线前真机点一遍关键路径（本次验收点 X 立刻暴露）。
- **案例**：B2d④ closing 事件双重对称 bug（拦截失效+destroy 被拦，821fc68 引入同日修复）。
- **为什么测试网没抓住**：嵌套 handler 不可直测（Event.set 聚合在库内部），只能源码字面锚 + 真机验收。

## 19. 过拟合 + 信息茧房（设计校准维度，非新增功能）
- **现象**：过拟合=对已知数据死记、缺泛化；信息茧房=对外部世界封闭、只强化偏好。小橘对应表现：字面死记/情绪回音室/高频霸屏/只记正反馈。
- **根因**：训练信号单一化+正反馈无阻尼（与 #13 自激同族，但此处指长期设计倾向而非运行时故障）。
- **修法模式**：⚠️ 定性=“校准目标”不是“新功能”——不加模块，只作**定期自检维度**（对照“四条标准即停”纪律）。防线=已有多机制（衰减/低权下沉/三乘子/联想扩散/无偏反馈 #314）。
- **案例**：2026-10-11 深夜讨论（用户主动学习概念，走学概念入口纪律——进坑库当“定期校准参照”，不进路线图当“新功能”）。
- **为什么测试网没抓住**：泛化/茧房是长程倾向，单测无断言面；靠四条标准验收用例（#320）定期人工校准。

## 20. 出口/入口消毒通道不对齐
- **现象**：QQ 通道输出污染——[think]/[plan] 方括号变体 + 裸 JSON 混合体直发用户（2026-10-12 早图片消息实锤）。
- **根因（三处叠加）**：①出口 `_strip_think` 只认 XML 尖括号 `<think>`，方括号变体不匹配；②出口 QQ 通道从未装 `_strip_bare_json`（控制台链专属补丁 0e10366/c871120）；③入口 CQ 码裸进 LLM 上下文（触发源）。
- **修法模式**：F1 出口（扩正则接方括号变体 + _strip_bare_json 口径改造接混合体，不能只 import）+ F2 入口（CQ 码转人类可读描述）。**防护装了一处，另一处漏装=通道不对齐族**（#14 删引用不删绑定 / #15 pytest 收集野文件同源）。
- **案例**：模型幻觉 `{"action":"show_image"}`（编造工具名+错键）+方括号 think/plan 直发；纯文字消息正常=差异点在 CQ 码进上下文。
- ⚠️ **单独立条**：CQ 码裸进上下文是**通用污染源**——image/record/file/video/at/face 等**全类型**都会撞，不止图片。
- **为什么测试网没抓住**：消毒口径按通道分装，测试各测各通道的“正常消息”，方括号变体×QQ 通道的组合无人覆盖。

## 21. 测试隔离掩盖集成断链（mock 全绿 ≠ 真链路通）
- **现象**：9 锚全绿，但真机上事件源从未被成功调用——#271③ Phase 0 自检 880 分钟张力恒 0、零 fire，无人察觉（2026-10-12 用户质询“张力事件源真接上了吗”才曝光）。
- **根因（三连）**：① 所有测试 mock 掉 `_collect_events`，只测引擎本体，从不测“真数据源→引擎”链路；② 事件源 SQL 查了 todos 表**不存在的列**（due_date——方案稿凭空写的，实施照抄未对 schema 核验），报错被裸 `except: pass` 吞掉；③ 报错无审计——引擎违反 #316 静默可解释纪律（880 分钟静默失败零记录）。
- **教训**：单元测试全绿 ≠ 集成能跑——“每个零件好”掩盖“零件之间没接”；裸 except 吞异常=定时炸弹，必须配审计；方案稿引用外部 schema 时必须先 PRAGMA 核验真实列名。
- **防线**：改外部数据源时补“真数据源→引擎”集成锚（不打 mock，环境级隔离）；裸 except 必配审计（失败第一天可见）；定期审“静默失败”——日志看不到报错≠没报错。
- **案例**：#271③ Phase 0（9 mock 锚全绿 + 真链路哑火，同日修复：真实列 created_at 老化 + event_source_error 审计 + 3 真集成锚）；同族：#270（以为没触发实则没接）、#14/#15（防护装一处漏一处）。
- **为什么测试网没抓住**：mock 的本义是隔离，副作用是遮蔽——被 mock 掉的恰好是唯一没被测的真实环节。

## 22. 同文件多步 replace 链的串匹配交叉覆盖
- **现象**：Edit 返回成功但实际写入被后续操作覆盖——brain.py `_normalize_think_labels` 替换后在同批次后续步骤中又被旧串部分重写，导致 import 替换回滚为旧函数定义。
- **根因**：同文件多步 replace 链中，前步 replace 改变了文本内容，后步 replace 的匹配范围（旧串）恰好与前步的替换输出交叉——两步各自"成功"但合并结果丢失了前步的变更。
- **修法模式**：①同文件多步改动用**脚本文件单次读→定位→替换→写→验证**（避免多步 Edit 的覆盖风险）；②每次写完**立即 grep 实抓验证**（不信断言返回值）；③复杂多步改动拆成多个脚本文件分别执行。
- **案例**：#326 补做——brain.py 四步编辑链中 normalize 替换被 _seal_bare_cot 插入覆盖，报"✅ 已迁"实为缩水。
- **为什么测试网没抓住**：Edit 返回成功=内存中替换成功，但**写入时机和覆盖行为**没有断言面。

## 23. 异常吞掉后部分生效（分步 commit 缺原子性）
- **现象**：#297 批 2 睡眠批处理——`_log` INSERT 占位符 6 个实参 5 个（漏 timestamp），异常被 try/except 吞掉；①night_decay 已 commit 而 ②replay 中断，幂等闸未写（2026-10-13 最小复现实锤：after=2.755 只剩衰减）。
- **后果**：单次部分生效（衰减落库+重放丢失）+ 次日重入不拦 = 全表**双重衰减**。
- **修法模式**：①多步写库合并**单事务**，任一步异常整体回滚=零部分生效；②幂等闸只在成功后写入（失败自然重试）；③吞异常必须配审计日志（#316 静默可解释同源）。
- **案例**：9948f21（_log 参数漏传 → 四步分步 commit 改单事务原子回滚连带修复）。
- **为什么测试网没抓住**：错误路径（SQL 绑定错）只在真跑 ② 时触发——锚只断言正常值、不带异常注入就会漏。

## 24. 增值源插入引擎链时失败必须静默让位
- **现象**：Open-Meteo 天气源插入手动链（SEARCH_ENGINE=bing）链首后，其失败（无位置/网络抖动）触发手动链「失败不降级」语义 → 整链报废返回 UNAVAILABLE（2026-10-13 dev 冒烟实锤）。
- **原则**：链上任何一环失败不阻断后续；**插入的增值源 ≠ 用户指定引擎**，不适用「锁定引擎快速失败」语义。
- **修法模式**：插入源在 except 分支按名字豁免（`if manual and name != "open_meteo": return UNAVAILABLE`）；或插入源独立 try 包裹。
- **案例**：9bdeeed（#329 批 A）。同族：#22 滤空短路（return 短路致后续引擎永不参与）——共通原则=链式结构里单环失败不得阻断后续环。
- **为什么测试网没抓住**：手动链+插入源失败的组合无人覆盖（各自单独测过）。

## 25. 前端动态 id 须进 id 对账白名单
- **现象**：#271③ 批 2 设置页「主动性」卡用 createElement 动态建 `proactive-audit` 审计框，console.js 里 `getElementById('proactive-audit')` 触发既有 id 对账加固测试（F4）假失败——console.js 引用了 index.html 不存在的 id。

## 26. pytest 类名前缀不合规 = 新锚静默不收集 = 假绿

## 27. WebView2 最小化恢复白屏（原生遮挡计算冻结渲染）
- **现象**：pywebview 窗口最小化恢复白屏 3-5 秒（用户体感，2026-10-13）。已设 --disable-backgrounding-occluded-windows + --disable-renderer-backgrounding（10-07 快改）仍白屏。
- **根因**：Chromium feature **CalculateNativeWinOcclusion**（Windows 原生遮挡计算）把最小化判为"完全遮挡"→合成器冻结出帧→恢复需重建渲染 3-5s——与后台优先级是**两条独立机制**，前者是 feature flag，后者是进程优先级；只设后者管不到前者。
- **修法**：--disable-features=CalculateNativeWinOcclusion + --disable-background-timer-throttling（后台定时器节流同步禁——前端轮询最小化期降频恢复积压）。代价=最小化期渲染进程内存/CPU 不释放（桌面常驻场景可接受，注释在案）。
- **验证坑两枚**：①浅色主题 UI 近白占比恒 ~0.89 是正常内容——"白比例"判据失效，白屏定性须截图目检；②窗口句柄泛词匹配（"小橘3号"误中同名文件夹窗口）——须用精确标题。
- **案例**：fb71884（desktop_launcher.py 四参数组合，真机 0.3s 即完整内容）。

## 28. 验收门形式与实质背离（机制在位但断言未咬合=绿而不真验）
- **现象**：黄金样本 27 条 `expected` 字段全空 → 比对模式 `if not expected: continue` 静默跳过 → 测试绿但零断言真执行（2026-10-14 #227 批 A 前置实锤：采集后回写 expected 才发现"门从未咬合过"）。
- **危害**：比 #26 更隐蔽一层——#26 是锚没被收集（总数对不上可查），本条是收集了、跑了、绿了，但断言被静默 continue（数字健康、门是假的）；两版黄金文件漂移（消费源 20 vs 扩展版 27）又叠加一层"扩了也没生效"。
- **修法**：①验收门落地时必须做**负测试**（故意改一条数据看是否 fail——"门会咬"才算门装好）；②比对类机制上线时 grep/读码实抓断言路径（确认 compare 分支真被执行）；③数据驱动的 expected 字段不许批量留空（空=跳过语义须在文档标红）；④数据文件与消费代码同源（单一事实源，防双文件漂移）。
- **案例**：0939cc3（#227 批 A：expected 回写后 38×2 断言首次真跑，当场拦下 _arg_after 漏抄一条 mismatch——门咬合后立即产生捕获，反证此前从未咬合）。同族：#26 假绿（收集静默跳过）/#14 删引用不删绑定（机制与数据两侧只装一侧）。
- **为什么测试网没抓住**：测试网本身就是要验证的对象——"验证者未验证"无法自证，只能靠流程纪律（负测试/实抓断言路径）兜底。
