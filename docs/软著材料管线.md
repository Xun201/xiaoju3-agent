## 三、修复轮三问题闭环（2026-10-04 核实定案）

| 现象 | 定性 | 结论 |
|---|---|---|
| WPS 显示 58 页 vs PDF 63 页 | WPS/LO 分页引擎差异（docx 无固定分页，WPS 重排更紧凑 ~8%） | 引擎差异，非缺陷；PDF 基准内 63 页双工具实测一致 |
| WPS 目录点击不跳转 | XML 结构零缺陷（anchor↔name 严格一致、bookmarkStart/End 齐全、75=75=75）；WPS 默认 Ctrl+单击跟随 | **用户实测 Ctrl+Click 跳转成功**，问题关闭 |
| 3.2.3 目录写 22、WPS 实际 21 | 跨引擎累积漂移（LO 基准内 75 条页码全自洽；WPS 重排后漂移随页数增长：开头 0 → 1/3 处 -1 → 书末约 -5） | 字面页码数学上不可能在两个引擎同时正确 → 换基准引擎或认 PDF 为准（A0 定案选后者） |

修复轮改摘要：build_docx.js 去 TableOfContents 域（旧版域断裂=75 条缓存仅 1 条在域内 + w:dirty 脏标记 → WPS 打开即新旧双目录叠加，此雷已根除）；新增 extract_toc_pages.py；layout_check.py 重写为统一页码口径；postprocess_footers.py 退役。

## 四、已知限制（A0 定案口径）

**K1（引擎分页漂移）**：docx 无固定分页——LibreOffice 排 63 页、WPS 排 58 页。设计说明书目录页码为 LO 基准冻结值，在 WPS 中打开时目录数字与 WPS 实际页面位置存在累积偏差（书末约 -5 页）。**提交 PDF 即无碍**（PDF 内目录页码与实际落页逐条相等，75/75 机验）；docx 仅作存档与再生成源，勿以 WPS 页码核对目录。
**K2（点击跳转操作习惯）**：WPS 需按住 Ctrl 单击目录条目才跳转（WPS/Word 默认行为，非缺陷）。
