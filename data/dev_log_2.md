# 小橘3号开发故事（倒叙）

## 🎬 结局：最新的状态

先说眼下这摊子事儿吧。

小橘3号——就是那块 Orange Pi 3B，8G 内存加 128G NVMe——现在处于一个“半身不遂但还有救”的状态。NVMe 里的 Ubuntu 22.04 被中文语言包给干趴了，进不去桌面，光标一闪一闪地嘲讽你。但好消息是：**SSH 大概率还能进**，网线 IP 是 `192.168.139.34`，WiFi 那个 `192.168.31.82` 也记在小本本上了。密码？老规矩，`orangepi`。

三条命脉还活着：
- **移动硬盘**挂载在 `/mnt/mobile-disk`，NTFS 格式，文件完好，就是权限改不动，当不了 Nextcloud 的数据目录，只能挂个“外部存储”的名分。
- **HDMI 小屏**这个老大难，换系统加降分辨率之后终于不频闪了，但触控还是废的——Type-C 口只供电不传数据，想触摸？老老实实插 USB。
- **手机投屏**在电脑上用 scrcpy 已经跑通了，触控也能用；开发板上想跑 scrcpy，adb 版本太旧，USB 一直 offline，凉凉。

新买的高速 TF 卡还在路上，旧 TF 卡刷的 Android 慢得跟蜗牛爬似的，根本进不去。所以现在的策略很明确：**等新卡一到，按八步走，先刷 Ubuntu 22.04 Xfce 到新 TF，再 dd 到 NVMe，一步都不能乱。**

顺便一提，中途还闹了个岔子——我去查 DeepSeek 有没有电脑客户端，结果绕了半天发现人家只有网页版，`chat.deepseek.com` 直接用浏览器打开就行，别去第三方下载站挨刀子。

## 🚧 历险：中间踩过的坑

说起踩坑，那真是一把辛酸泪。

**第一个大坑：中文语言包。** 我寻思系统都装好了，不得把中文安排上？结果 `apt install language-pack-zh*` 一下去，好家伙，桌面直接暴毙，重启之后光标在黑屏上闪啊闪，进不去图形界面。这就是典型的“好心办坏事”。后来才知道，得先换国内源、`apt update` 完了再装，顺序错了就是给自己挖坟。

**第二个坑：HDMI 频闪。** 小屏接上去，画面一闪一闪的，眼睛都快瞎了。查了半天，结论是 RK3566 和 iPad 改屏驱动板八字不合。最后换系统加降分辨率，才算把这事儿摁下去。你说折腾不折腾？

**第三个坑：小屏供电。** 我用 Type-C 插电脑 USB 口供电，屏幕闪一下黑一下，跟鬼片似的。后来发现必须插插排，电脑 USB 那点电根本喂不饱它。而且 Type-C 只供电，不传数据，触控想都别想，老老实实走 USB。

**第四个坑：开发板的 ARM 架构。** 我一开始还想在上面跑 ComfyUI、MaiBot 这些 Windows 软件，结果人家是 ARM，根本跑不了。这属于常识性翻车，丢人。

**第五个坑：scrcpy 投屏。** 电脑上跑 scrcpy 顺风顺水，触控也能用，我以为开发板上也一样。结果一跑，adb 版本太旧，USB 一直 offline，怎么搞都不行。这就是典型的“彼之蜜糖，我之砒霜”。

**第六个坑：移动硬盘 NTFS 权限。** 我想把移动硬盘直接当 Nextcloud 的数据目录，结果 NTFS 格式权限改不动，`chown`、`chmod` 全试了，跟挠痒痒似的。最后只能挂载到 `/mnt/mobile-disk` 当外部存储用，数据目录还得放 NVMe 上。

**第七个坑：Ping 超时。** 网线插好了，第二步能 Ping 通，后面全部超时丢包。IP 段是 `192.168.139.x`，笔记本是 `.1`，开发板是 `.34`，看着没问题，但就是丢包。可能是防火墙、网卡状态、或者网线接触不良，得一步步排查。

最惨的是那次 **NVMe 系统损坏**——装中文包卡死之后，系统直接进不去桌面。我试了 Ctrl+Alt+F2 进 TTY，能进；试了 SSH，也能进。但图形界面就是起不来。最后判断是中文包把桌面环境搞崩了，得卸掉 `language-pack-zh*` 才能救。如果 TTY 都进不去，那就只能等新 TF 卡，用 TF 启动后挂载 NVMe 备份数据，然后 dd 重刷。

这中间还有个小插曲：我一开始不知道怎么进命令行，连 SSH 都不会用。后来才知道，笔记本 PowerShell 里直接 `ssh orangepi@192.168.139.34`，密码输 `orangepi`，第一次问 yes/no 输 yes 就行。本地的话，开机卡光标时按 Ctrl+Alt+F2，不行就 F3-F6 挨个试，有些键盘还得按 Fn+F2。

## 🚀 起源：最早发生的事

故事得从最开始说起。

我搞了一块 Orange Pi 3B，RK3566 的芯片，8G 内存，128G NVMe，想把它做成一台 24 小时不关机的小主机——下载机、私有云、去广告、远程桌面，全都要。而且我坚持要 HDMI 直出小屏幕，不走远程，就要那种“看得见摸得着”的感觉。

一开始信心满满，刷了 Ubuntu 22.04 到 NVMe，装好系统，配好网络，VNC 地址 `http://IP:6080/vnc.html` 也记下了，账号密码 `orangepi/orangepi`，一切看着挺顺利。

然后就是那个致命的操作——**装中文语言包**。我当时想，系统都跑起来了，不得汉化一下？结果 `apt install language-pack-zh*` 一执行，桌面直接卡死，重启之后光标在黑屏上闪，进不去图形界面了。这就是整个故事的开端，也是最大的转折点。

再往前推，其实还有更早的坑：HDMI 小屏频闪、Type-C 供电不足、旧 TF 卡 Android 太慢、移动硬盘 NTFS 权限改不动……这些都是在一开始折腾硬件的时候踩的。但真正让整个项目卡住的，还是那个中文语言包。

现在回头看，如果当时先换源、先 `apt update`、最后再装中文包，可能就没这事儿了。但谁知道呢？踩坑就是这样，不亲自摔一跤，永远记不住。

## 💡 预告：下一轮要做什么

新 TF 卡一到，咱们就按这个顺序来，一步都不能乱：

| 步骤 | 操作 | 目的 |
|------|------|------|
| 1 | 刷 Ubuntu 22.04 Xfce 到新 TF 卡 | 先有稳定可启动系统 |
| 2 | 插 TF 启动，换国内源，apt update/upgrade | 避免装中文包卡死 |
| 3 | 确认 NVMe 可擦，dd TF 到 NVMe | 迁移系统到 NVMe |
| 4 | 刷完拔 TF，只留 NVMe 启动 | 防止 UUID 冲突 |
| 5 | 进 NVMe 系统后扩分区、装中文、字体 | 系统稳定后再配置 |
| 6 | 重装 VNC/noVNC、qBittorrent、AdGuard Home、Nextcloud、Chromium | 恢复服务 |
| 7 | Nextcloud 数据目录放 NVMe，移动硬盘用外部存储挂载 | 避开 NTFS 权限坑 |
| 8 | 最后再搞手机投屏+触控优化 | 不影响主机稳定 |

关键提醒：`sudo dd if=/dev/mmcblk1 of=/dev/nvme0n1 bs=4M status=progress` 这条命令可用，但克隆后 TF 和 NVMe 的 UUID 会一样，务必刷完拔 TF 或改 UUID，否则启动项容易乱。中文语言包建议最后装，且先换源、更新完 apt 再装。

另外，网络那块还得继续排查 Ping 超时的问题，确认开发板 IP `192.168.139.34` 是否可达。如果 SSH 能进，就先修系统；如果 TTY 都进不去，就直接重刷，别死磕。

等新卡到了，你说一声“开始”，我就手把手带你走完这八步。这次咱们不装中文包，先让系统稳如老狗，再慢慢折腾那些花里胡哨的东西。
