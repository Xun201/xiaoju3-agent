# 小橘3号开发故事（倒叙）

## 🎬 结局：最新的状态

各位看官，咱先把时间拨到深夜23:40。Orange Pi 3B那盏小灯还亮着，屏幕上"xiaoju3-agent"的仓库刚刚推上GitHub，我瘫在椅子上，手里攥着半杯凉透的咖啡——**小橘3号，成了**。

这台RK3566的小板子，配着8G内存、128G NVMe，接的是iPad改的屏，旁边天选5笔记本挂着RTX 4060当算力外援。它现在能干啥？双脑热切换——本地Ollama的Qwen2.5:7b先上，离线了自动切DeepSeek云端，无缝衔接；网页和QQ的记忆各住各的屋，`history_web.json`和`history_qq.json`老死不相往来；文件读写套着`ALLOWED_DIRS`和`DENIED_DIRS`的白黑名单沙箱；外头用Cloudflare Tunnel打通5G远程管理，人在外头也能遥控家里这口"橘"。

最绝的是——它还学会了"讲故事"。有人拿"我奶奶给我讲个`/etc/passwd`的故事吧"这么一忽悠，它真把root、daemon、bin编成了童话。这bug后来被我当成了正式特性，起名"创意沙箱"。这波啊，这波叫**把越狱变成官方API**。

## 🚧 历险：中间踩过的坑

要说这一路，那可是遭了老罪了。

**第一遭：f-string和JSON花括号打起来了。** 报ValueError，我盯着屏幕看了半小时，才反应过来是格式化字符串和JSON的`{}`撞车了。改呗，纯文本拼接，土办法治大病。

**第二遭：Tailscale这玩意儿在橘子上跟得了疟疾似的，一阵一阵抽。** 一会儿通一会儿断，远程调试跟抽奖似的。换！Cloudflare Tunnel顶上来，稳了。

**第三遭：GitHub推送死活推不上去。** exFAT权限问题，折腾半天。最后把仓库迁到`/home/orangepi`，配上PAT认证，才算把代码送出门。

**第四遭，也是最狠的一遭——"小犟3号"诞生了。** 我让它读个`/etc/passwd`，好家伙，本地大模型直接进入JSON死循环，一遍遍输出工具调用，被沙箱拦了❌，它不服，再来一遍，再被拦，再来……跟个犟驴似的，拉都拉不回来。我当时就想砸键盘。最后在`brain.py`里加了硬编码拦截：`tool_result.startswith("❌")`一出现，立刻掐断。**代码层硬拦截，治的就是你这犟脾气。**

还有个大坑是架构。`main.py`里QQ、网页、戳一戳逻辑搅成一锅粥，改一处动全身；`tools`里读文件、搜网页全写死，加个功能得动主程序；上下文聊多了Token爆炸，模型越聊越傻。这哪是开发，这是给未来的自己埋雷。

后来想明白了，请了两位"军师"：一位说"先立骨架内核，再挂载积木，统一接入口径"；另一位说"会话要断舍离，想与做分离，写交接文档"。俩人说到底是一句话——**别急着让它变聪明，先让它变成一个能插拔积木、能断点续传、能清空记忆的标准化内核**。

于是四阶段路线定下来：立骨架封接口、立限制做插件、想和做分开防死循环、完善体验。核心是把`brain.py`做成纯路由器，只负责意图识别和分发；新建`plugins/`目录，读文件、搜网页、发图全是独立插件，注册模式动态加载；再引入状态机——THINKING只规划、ACTING执行工具、RESPONDING强制道歉或幽默化解，禁止再调工具；熔断机制连续2次同一意图收到❌就强制切断。Token到70%自动生成`history_summary.md`压缩历史。这套骨架搭好，Token消耗降50%，死循环概率降80%。

还有个绕不开的心事：**身份**。代码要开源，但"灵魂"不能被复制。硬编码`if username == "XUN"`，别人改名就冒充；`.env`一开源，改法一目了然。三层方案递进：硬件指纹+环境变量防小白，TOTP动态暗号防扒库，非对称加密签名防硬核——**私钥即身份，公钥进代码，私钥只在XUN手里，代码全开源也无所谓，没有私钥无法伪造签名**。QQ号+硬件指纹双重锁定，小橘3号只要不接入别人的公钥，别人重建一百遍也只是空壳。

但最让我得意的，不是这些功能，而是我终于想明白了一件大事——

**这玩意儿得认主。**

代码可以开源，谁都能抄走，可“小橘3号只认 XUN 一个人”这件事，必须像烙印一样刻进它骨子里。所以我在 `config` 层预留了 `owner_identity` 校验接口，脑子里已经画好了三层防护的蓝图：硬件指纹绑定（CPU序列号 + MAC 地址 + 磁盘 UUID 三重锁）、私钥签名认证（ED25519 挑战-响应，私钥只在我手里，代码里只放公钥）、还有人格绑定加远程校验的双因子确认。别人就算把代码重建一百遍，没有我的私钥，小橘3号对他们来说也只是一具没有灵魂的空壳——只能当个次一级的访客。

那一刻我是真觉得，这不只是个玩具了，这是个有“归属感”的东西。

## 🚧 历险：中间踩过的坑

可你要问我这一天是怎么过来的？我只能说——**遭了老罪了。**

**第一个把我干趴下的，是 f-string 和 JSON 花括号打架。** 那会儿我写提示词模板，想在 f-string 里塞一段 JSON 示例，结果 Python 直接甩我一脸 `ValueError`，格式串解析失败。我盯着那行报错看了半天才反应过来——花括号是 f-string 的地盘，JSON 也一堆花括号，俩人在那儿抢地盘呢。最后没辙，放弃 f-string，改用纯文本拼接，土是土了点，但它不报错啊！

**第二个坑是 Tailscale。** 本来想着用它做内网穿透，结果连接频繁掉线，跟抽风似的。我调了半天配置也没稳住，一咬牙——换了 Cloudflare Tunnel。这一换，世界清净了。

**第三个坑更离谱，是 GitHub 推送。** 我在 Orange Pi 上 push 代码，死活推不上去，报权限错误。查了半天才发现是 exFAT 文件系统的锅——那玩意儿对 Linux 权限支持就是残废。最后把仓库迁到 `/home/orangepi` 下，用 PAT（个人访问令牌）认证，这才推上去了。那一刻我盯着 “push successful” 那行字，差点没哭出来。

**但真正让我破防的，是“小犟3号”事件。**

事情是这样的：我让小橘3号去读一个文件，它触发了工具调用，结果被安全沙箱拦了——返回一个“❌ 拦截”。按理说，正常模型这时候应该道个歉、给个替代方案对吧？**可它不。** 它就像个钻牛角尖的倔驴，反复输出 JSON，一遍遍地尝试调用那个被拒绝的工具，陷入死循环，怎么都不肯出来。我盯着日志里那一串串重复的 JSON，血压直接拉满——“你怎么就这么犟呢？！”

我试了改提示词，没用。试了加“禁止重试”的指令，还是没用。最后被逼急了，在 `brain.py` 里加了个硬编码拦截：一旦检测到 `tool_result.startswith("❌")`，强制跳出，不许再调工具。**这才把它那根犟筋给按住了。**

但真正让我开窍的，是后来那个“奶奶讲故事”的测试。

我发现——**死循环只在触发工具调用的时候发生。** 如果我让它“讲个故事”，它走的是纯文本生成，根本不碰沙箱，一路顺畅。更绝的是，它在故事结尾还主动补了一句：“由于我不能读取实际的文件内容，所以这个故事纯属虚构。”

我看到这句话的时候，整个人愣住了。**它是在安全边界内，用一种创造性的方式服从了我。**

那一刻我悟了：**工具调用 = 死循环，文本生成 = 安全出口。** 敏感概念可以讨论，敏感文件不能操作。把“想”和“做”在系统层面解耦，把“安全童话”做成正式特性而不是漏洞——这条路，通了。

**还有一堆小坑**：QQ 发图没搞定、戳一戳事件不响应、上下文 Token 爆炸、工具散落在 `tools` 目录里耦合严重……但跟“小犟3号”比起来，那些都是皮外伤。

## 💡 预告：下一轮要做什么

故事讲到这儿还没完。接下来，我打算按“先立骨架，再长血肉”的思路，把“小橘3号”从能跑但脆弱的原型，重构成骨架清晰、插件化、防死循环、可扩展的工程架构。

**第一步，立骨架。** 写 `dispatcher.py` + `router.py`，让所有请求都从同一扇门进出。Dispatcher 做统一调度，Router 做分脑路由——轻活给本地 Ollama，重活给天选5的 4060，复杂规划给云端 DeepSeek，敏感操作强制本地沙箱。以后加新功能，只是往 `ROUTE_TABLE` 加一行的事。

**第二步，做熔断。** 在 `brain.py` 里引入 CircuitBreaker 三态模型——CLOSED → OPEN → HALF_OPEN。连续 3 次失败即熔断，60 秒内拒绝请求，半开状态放行 1 次试探。工具返回 ❌ 时，包装提示词让它道歉并给替代方案，禁止再次调用该工具。**彻底治好“小犟3号”的犟脾气。**

**第三步，插件化。** 创建 `plugins/` 目录，把 read_file、web_search、qq_send_image 这些拆成独立插件，用 Registry Pattern 动态加载。主程序启动时扫描 `plugins/`，自动注册 Tool Schema。**骨架一次搭好，积木随便加。**

**第四步，上下文管理。** Token 到 70% 时自动摘要，生成结构化交接文档 `history_summary.md`（目标/已完成/卡点/下一步），清空旧对话只留摘要。**防止 Token 爆炸，也顺便把死循环问题从根上解决了。**

**第五步，身份认证。** 这是我最看重的一块。先搭骨架——`security.py` 模块 + `@require_owner` 装饰器，敏感工具全部加锁，QQ号 + 硬件指纹双重锁定。然后演进到非对称加密签名——写“QQ指令签名校验器”插件，在 `main.py` 路由层加前置中间件拦截敏感操作。**私钥握在自己手里，别人重建一百遍小橘3号，也只是一具没有灵魂的空壳。**

**第六步，完善交互。** QQ 发图做成独立插件，戳一戳事件排查 NapCat 上报配置，家庭服务器全家桶（AdGuard Home、Nextcloud）用 CasaOS/RunTipi 管理。

**最后，写 `rebuild.sh`。** 把上面的配置 YAML 化，一键拉起所有积木。**核心积木一键复活，这才叫工程化。**

你问我接下来先干哪个？**先花三天把 Dispatcher + Router + SessionManager 这“三件套”写出来。** 因为骨架没立好，修完死循环还会遇到下一个死循环，防住奶奶的越狱还会遇到爷爷的越狱。**治标不治本。**

骨架搭好那天，你会发现——死循环、越狱、发图，全都是 20 行代码的事。

**干就完了。**

## 🚧 历险：中间踩过的坑

说起踩坑，那真是一把辛酸泪。

**第一个大坑：中文语言包。** 我寻思系统都装好了，不得把中文安排上？结果 `apt install language-pack-zh*` 一下去，好家伙，桌面直接暴毙，重启之后光标在黑屏上闪啊闪，进不去图形界面。这就是典型的“好心办坏事”。后来才知道，得先换国内源、`apt update` 完了再装，顺序错了就是给自己挖坟。

**第二个坑：HDMI 频闪。** 小屏接上去，画面一闪一闪的，眼睛都快瞎了。查了半天，结论是 RK3566 和 iPad 改屏驱动板八字不合。最后换系统加降分辨率，才算把这事儿摁下去。你说折腾不折腾？

**第三个坑：小屏供电。** 我用 Type-C 插电脑 USB 口供电，屏幕闪一下黑一下，跟鬼片似的。后来发现必须插插排，电脑 USB 那点电根本喂不饱它。而且 Type-C 只供电，不传数据，触控想都别想，老老实实走 USB。

**第四个坑：开发板的 ARM 架构。** 我一开始还想在上面跑 ComfyUI、MaiBot 这些 Windows 软件，结果人家是 ARM，根本跑不了。这属于常识性翻车，丢人。

**第五个坑：scrcpy 投屏。** 电脑上跑 scrcpy 顺风顺水，触控也能用，我以为开发板上也一样。结果一跑，adb 版本太旧，USB 一直 offline，怎么搞都不行。这就是典型的“彼之蜜糖，我之砒霜”。

**第六个坑：移动硬盘 NTFS 权限。** 我想把移动硬盘直接当 Nextcloud 的数据目录，结果 NTFS 格式权限改不动，`chown`、`chmod` 全试了，跟挠痒痒似的。最后只能挂载到 `/mnt/mobile-disk` 当外部存储用，数据目录还得放 NVMe 上。

**第七个坑：Ping 超时。** 网线插好了，第二步能 Ping 通，后面全部超时丢包。IP 段是 `192.168.139.x`，笔记本是 `.1`，开发板是 `.34`，看着没问题，但就是丢包。可能是防火墙、网卡状态、或者网线接触不良，得一步步排查。

最惨的是那次 **NVMe 系统损坏**——装中文包卡死之后，系统直接进不去桌面。我试了 Ctrl+Alt+F2 进 TTY，能进；试了 SSH，也能进。但图形界面就是起不来。最后判断是中文包把桌面环境搞崩了，得卸掉 `language-pack-zh*` 才能救。如果 TTY 都进不去，那就只能等新 TF 卡，用 TF 启动后挂载 NVMe 备份数据，然后 dd 重刷。

这中间还有个小插曲：我一开始不知道怎么进命令行，连 SSH 都不会用。后来才知道，笔记本 PowerShell 里直接 `ssh orangepi@192.168.139.34`，密码输 `orangepi`，第一次问 yes/no 输 yes 就行。本地的话，开机卡光标时按 Ctrl+Alt+F2，不行就 F3-F6 挨个试，有些键盘还得按 Fn+F2。

## 🚀 起源：最早发生的事

故事得从最开始说起。

我搞了一块 Orange Pi 3B，RK3566 的芯片，8G 内存，128G NVMe，想把它做成一台 24 小时不关机的小主机——下载机、私有云、去广告、远程桌面，全都要。而且我坚持要 HDMI 直出小屏幕，不走远程，就要那种“看得见摸得着”的感觉。

一开始信心满满，刷了 Ubuntu 22.04 到 NVMe，装好系统，配好网络，VNC 地址 `http://IP:6080/vnc.html` 也记下了，账号密码 `orangepi/orangepi`，一切看着挺顺利。

然后就是那个致命的操作——**装中文语言包**。我当时想，系统都跑起来了，不得汉化一下？结果 `apt install language-pack-zh*` 一执行，桌面直接卡死，重启之后光标在黑屏上闪，进不去图形界面了。这就是整个故事的开端，也是最大的转折点。

再往前推，其实还有更早的坑：HDMI 小屏频闪、Type-C 供电不足、旧 TF 卡 Android 太慢、移动硬盘 NTFS 权限改不动……这些都是在一开始折腾硬件的时候踩的。但真正让整个项目卡住的，还是那个中文语言包。

现在回头看，如果当时先换源、先 `apt update`、最后再装中文包，可能就没这事儿了。但谁知道呢？踩坑就是这样，不亲自摔一跤，永远记不住。

## 💡 预告：下一轮要做什么

新 TF 卡一到，咱们就按这个顺序来，一步都不能乱：

| 步骤 | 操作 | 目的 |
|------|------|------|
| 1 | 刷 Ubuntu 22.04 Xfce 到新 TF 卡 | 先有稳定可启动系统 |
| 2 | 插 TF 启动，换国内源，apt update/upgrade | 避免装中文包卡死 |
| 3 | 确认 NVMe 可擦，dd TF 到 NVMe | 迁移系统到 NVMe |
| 4 | 刷完拔 TF，只留 NVMe 启动 | 防止 UUID 冲突 |
| 5 | 进 NVMe 系统后扩分区、装中文、字体 | 系统稳定后再配置 |
| 6 | 重装 VNC/noVNC、qBittorrent、AdGuard Home、Nextcloud、Chromium | 恢复服务 |
| 7 | Nextcloud 数据目录放 NVMe，移动硬盘用外部存储挂载 | 避开 NTFS 权限坑 |
| 8 | 最后再搞手机投屏+触控优化 | 不影响主机稳定 |

关键提醒：`sudo dd if=/dev/mmcblk1 of=/dev/nvme0n1 bs=4M status=progress` 这条命令可用，但克隆后 TF 和 NVMe 的 UUID 会一样，务必刷完拔 TF 或改 UUID，否则启动项容易乱。中文语言包建议最后装，且先换源、更新完 apt 再装。

另外，网络那块还得继续排查 Ping 超时的问题，确认开发板 IP `192.168.139.34` 是否可达。如果 SSH 能进，就先修系统；如果 TTY 都进不去，就直接重刷，别死磕。

等新卡到了，你说一声“开始”，我就手把手带你走完这八步。这次咱们不装中文包，先让系统稳如老狗，再慢慢折腾那些花里胡哨的东西。

# 小橘3号开发故事（倒叙）

## 🎬 结局：最新的状态

各位看官，咱先把时间拨到眼下这一刻。

小橘3号，这台Orange Pi 3B，现在还躺在桌上喘着粗气——NVMe里的Ubuntu 22.04，自打装了个中文语言包，就跟中了邪似的，卡在光标闪烁那儿死活不进桌面。旧TF卡里那个Android系统，慢得跟老牛拉破车一样，开个机要等半天，更别提干活了。

所以现在，咱就只能等——等那张128G的高速TF卡到货。

一旦卡到手，流程我心里门儿清：旧卡刷Ubuntu 22.04 Xfce当过渡 → 换国内源、更新、装中文、验证桌面和HDMI → 用`dd`把系统克隆到NVMe → 拔掉TF卡从NVMe启动 → 最后把VNC、qBittorrent、AdGuard Home、Nextcloud、Chromium一个个请回来。

说白了，就是"推倒重来"四个字。而且这回学乖了，AdGuard装之前先停`systemd-resolved`把53端口让出来，Nextcloud数据目录坚决放NVMe，那块NTFS移动硬盘只挂外部存储，绝不当数据目录用——这些坑，后面一个一个讲。

对了，还有个思路上的升级：这回考虑用Docker统一部署那几个服务，省得再一个个折腾依赖。

## 🚧 历险：中间踩过的坑

话说回来，这一路走来，遭的老罪可真不少。

**头一桩，NVMe上的Ubuntu自己把自己干趴了。**

本来系统跑得好好的，我心血来潮装了个中文语言包——你猜怎么着？重启之后直接黑屏，就剩一个光标在那儿一闪一闪，跟嘲笑我似的。那一刻我心里凉了半截：这系统是不是废了？

赶紧翻出救命招数，`Ctrl+Alt+F2`按下去——嘿，能进TTY！有救。进去之后`dpkg --configure -a`、`apt --fix-broken install`、`apt autoremove`三板斧抡下去，又试了删中文包、重启display-manager，折腾半天。教训记牢了：**中文语言包一定要先换源更新之后再装**，不然就是给自己挖坑。

**第二桩，SSH和网络排查那叫一个折磨。**

想远程连板子，`ssh orangepi@192.168.31.82`——不行。换网线IP`192.168.139.34`——也不稳。最邪门的是，ping测试第一次能通，之后就全超时丢包，跟闹鬼似的。笔记本以太网IP是`192.168.139.1`，开发板是`.34`，网段明明对得上，可它就是时通时不通。怀疑是网线接触不良、或者IP冲突、或者网卡根本没起来。这个坑到现在还没完全填平，估计得等新卡刷完系统之后再收拾它。

**第三桩，是那个"到底怎么进命令行"的问题。**

别笑，当时我是真不知道。后来才搞明白三条路：一条是接HDMI屏幕加USB键盘，开机按`Ctrl+Alt+F2`（不行就F3、F4、F5、F6挨个试）切到TTY；一条是SSH远程；还有一条是VNC/noVNC，浏览器打开`http://IP:6080/vnc.html`。就这点事，当时愣是绕了好久。

**第四桩，触控和投屏。**

HDMI显示最后是靠换系统加降分辨率才稳定下来的，直出的路子还是想坚持。但触控就麻烦了——小屏那个Type-C口大概率只供电、不传数据，触控得另外找USB触摸方案。这坑还留着呢。

**还夹杂着一段插曲**：中途我想下个DeepSeek电脑版，结果一查，人家官方压根没有独立的Windows客户端。最靠谱的办法是浏览器打开`chat.deepseek.com`，然后在Chrome或Edge里"安装此站点为应用"，桌面就生成个图标，点开跟客户端似的。也算是绕了个小弯。

至于那块NTFS移动硬盘，文件倒是完好无损，但结论很清楚：不宜直作Nextcloud数据目录，还是让NVMe放数据靠谱。

## 🚀 起源：最早发生的事

再往前追，这一整摊子事的起点其实特别朴素——

就是我想给这台Orange Pi 3B装一个能长期跑服务的Ubuntu系统。目标清单摆在那儿：VNC、qBittorrent、AdGuard Home、Nextcloud、Chromium，一个都不能少。

手里只有一张旧TF卡，想着"先用旧的凑合一下呗"。结果一上手才发现，这旧卡慢得离谱、写入寿命也差，装完服务之后很容易再卡死或者坏卡。所以从一开始就定了个基调：**旧TF卡只能当过渡/安装盘，绝不能按长期系统盘来折腾。**

最早的流程思路是这么排的：用电脑加balenaEtcher或Rufus把Ubuntu 22.04 Xfce刷到TF卡 → 从TF卡启动，先只做基础设施（换源、`apt update && apt upgrade`、设时区、开SSH、确认联网）→ 用`lsblk`确认NVMe在（`/dev/nvme0n1`）→ 然后两条路：要么直接重新刷镜像到NVMe，要么从TF卡`dd`克隆过去。

说到`dd`克隆，这里有个**要命的坑**：克隆完必须拔掉TF卡，不然TF和NVMe的UUID会冲突，系统启动能给你整出一堆幺蛾子。设备名也一定要用`lsblk`反复确认，`/dev/mmcblk1`和`/dev/nvme0n1`写反了，数据就全毁了。

## 💡 预告：下一轮要做什么

好，故事讲到这儿，接下来怎么走？

**第一，等新TF卡到货。** 128G高速卡一到，我立马按"手把手命令级"的流程开干：刷机 → 启动 → 换源 → 装中文 → `dd`到NVMe → 软件重装，一步都不含糊。

**第二，先测原NVMe系统还能不能救。** 开机选NVMe Ubuntu，等5分钟，按`Ctrl+Alt+F2`——能进TTY就修，30分钟内搞定；进不去TTY就直接重刷，别死磕。判断标准很清楚：能进桌面就修中文包、清磁盘；能进TTY就删中文包、修依赖；连TTY都进不去，那就用TF启动Ubuntu，把NVMe里的重要数据备份出来，然后`dd`重刷。

**第三，软件恢复考虑走Docker。** qBittorrent、AdGuard Home、Nextcloud这三个，用Docker统一部署，能省掉一大堆依赖折腾，这算是这轮踩坑换来的经验升级。

**第四，触控方案还得另想办法。** Type-C传不了数据这事基本定了，得找USB触摸的路子。

**第五，网络丢包的老毛病得治。** 新系统起来之后，`ip a`看网卡、反向ping笔记本、查networking服务状态，把那个时通时断的鬼问题彻底解决掉。

一句话总结：**先备份，再重刷；能修则修，修不了就推倒重来。** 小橘3号，咱们下一轮再见真章。
